\begin{abstract}
Deploying large language models (LLMs) on resource-constrained consumer GPUs (e.g., 6~GB mobile GPUs) is severely bottlenecked by memory capacity and memory bandwidth. Standard speculative decoding pipelines accelerate autoregressive generation by pairing a large target model with a smaller auxiliary draft model; however, hosting this auxiliary model incurs substantial additional VRAM (typically 1.5--3.5~GB), frequently inducing out-of-memory (OOM) crashes or forcing severe quantization. 

In this work, we propose \textbf{Zero-Additional-Model-Weight-VRAM Self-Speculative Decoding (ZASSD)}, an end-to-end framework enabling high-throughput speculative decoding with \textbf{0.0~MB} of additional weight memory. ZASSD achieves this by deriving an ultra-fast draft model dynamically from the target model itself via empirical and Centered Kernel Alignment (CKA) layer-skipping, coupled with zero-copy sharing of the verified KV prefix. To navigate complex tradeoffs between draft fidelity, verification latency, device power, and operating temperature, we introduce the \textbf{Hardware-Aware Joint Controller} powered by model-specific profiles and a constrained throughput maximization objective ($\max \widehat{\text{TPS}}$ s.t. physical barriers).

Evaluated under an identical, frozen protocol on both \textbf{Qwen2.5-3B-Instruct} (36 layers) and \textbf{Llama-3.2-3B-Instruct} (28 layers) in 4-bit NormalFloat (NF4) quantization against five competitive baselines (Vanilla, Fixed CKA-75, Adaptive $K$, adapted KnapSpec, and adapted SpecBound) as well as canonical reasoning (GSM8K), coding (HumanEval), and summarization (CNN/DailyMail) benchmarks, ZASSD achieves up to \textbf{89.1\% token acceptance rate}, retains \textbf{0.89$\times$--1.05$\times$ relative throughput} (up to \textbf{1.14$\times$ on reasoning and 1.39$\times$ on structured contexts}) while eliminating 1.5--2.5~GB of auxiliary weight memory, strictly enforces physical thermal (82$^\circ$C) and memory limits, and mathematically bounds logit divergence within the 4-bit NF4 GEMM dequantization noise envelope ($\Delta \le 2\|L\|_\infty$).
\end{abstract}

\section{Introduction}
\label{sec:intro}

Large language model (LLM) inference on consumer edge hardware---such as laptops equipped with 6~GB mobile GPUs---faces two physical bottlenecks:
\begin{enumerate}
    \item \textbf{Memory Capacity Bottleneck:} A 3B-parameter model requires approximately 2.0--2.2~GB of VRAM in 4-bit NormalFloat (NF4) quantization~\cite{dettmers2023qlora}, while a 7B model occupies 3.95~GB. Adding a dedicated draft model (e.g., 0.5B to 1.5B parameters) consumes an additional 1.0--3.0~GB of VRAM, leaving negligible headroom for KV caches, activations, and operating system overhead. On 6~GB consumer GPUs, this immediately triggers CUDA Out-Of-Memory (OOM) crashes.
    \item \textbf{Memory Bandwidth Bottleneck:} On entry-level consumer GPUs (such as the NVIDIA RTX 4050 Laptop GPU with a 96-bit memory bus providing 192~GB/s bandwidth), single-token forward passes take only 18--24~ms for a 3B NF4 model. In standard speculative decoding~\cite{leviathan2023fast,chen2023accelerating}, generating $K$ draft tokens takes $T_{\text{draft}}$ and parallel verification takes $T_{\text{verify}}$. Positive speedup is realized if and only if:
    \begin{equation}
        \mathbb{E}[N] \times T_{\text{vanilla}} > T_{\text{draft}}(K) + T_{\text{verify}}(K)
    \end{equation}
    where $\mathbb{E}[N]$ is the expected number of accepted tokens per step. When memory bandwidth is constrained, draft model execution cannot be arbitrary; inefficient draft configurations degrade throughput below autoregressive baselines ($< 1.0\times$).
\end{enumerate}

To overcome these constraints, we introduce \textbf{ZASSD}, featuring four primary contributions:
\begin{enumerate}
    \item \textbf{Zero-Additional-Weight Architecture \& Static KV Sharing:} We eliminate auxiliary model storage entirely by dynamically skipping redundant transformer layers of the target model during the draft phase. We implement a pre-allocated static KV cache with zero dynamic allocations and $O(1)$ rollback.
    \item \textbf{Empirical Greedy Layer Selection:} Rather than relying exclusively on representation heuristics (e.g., CKA~\cite{kornblith2019similarity}), we develop an empirical greedy search maximizing target token agreement, identifying layer subsets ($S \in \{\texttt{emp\_4}, \dots, \texttt{emp\_10}\}$) retaining up to 100\% top-1 match accuracy.
    \item \textbf{Hybrid Zero-VRAM Speculative Engine:} We integrate zero-cost Prompt Lookup Decoding (PLD)~\cite{saxena2024prompt} with layer-skipping into a hybrid engine, realizing $>1.0\times$ speedup across diverse NLP tasks.
    \item \textbf{Physical Feasibility Proof \& Open Artifacts:} We formally document the OOM boundary where standard 0.5B/1.5B auxiliary draft models crash, while ZASSD operates with 0.0~MB weight overhead.
\end{enumerate}

\section{System Architecture \& KV Invariants}
\label{sec:system}

In ZASSD, model weight memory overhead is strictly \textbf{0.0~MB}. For dynamic key-value storage, we establish the principle of \textbf{zero-copy sharing of the verified prefix} supported by a pre-allocated static circular buffer.

Four core systems invariants govern the cache lifecycle:
\begin{enumerate}
    \item \textbf{Invariant 1 (Zero-Copy Prefix Sharing):} When an ephemeral draft cache is forked, key and value pointers alias the target cache: $\texttt{dl.keys.data\_ptr()} == \texttt{tl.keys.data\_ptr()}$. Zero bytes are allocated for prefix duplication.
    \item \textbf{Invariant 2 (Target KV State Isolation):} Draft writes are directed strictly to the speculative suffix $[P, P+K)$. The target prefix $[0, P)$ remains bitwise identical.
    \item \textbf{Invariant 3 (Canonical Rejection Rollback):} Unaccepted candidate tokens are cleanly rolled back via pointer manipulation ($\texttt{target\_kv.crop(P + accepted)}$) in $O(1)$ time without tensor reallocations.
    \item \textbf{Invariant 4 (Suffix-Bounded Dynamic Memory):} Dynamic memory overhead during speculation is strictly bounded by $K \times d_{\text{head}} \times N_{\text{heads}} \times \text{layers} \le 8\text{~MB}$.
\end{enumerate}

\section{Hardware-Aware Joint Controller}
\label{sec:controller}

We formulate runtime action selection $(S, K)$ as a constrained throughput maximization problem:
\begin{equation}
    \max_{S, K} \widehat{\text{TPS}}(S, K) - \lambda_{\text{energy}} \widehat{E}(S, K)
\end{equation}
subject to:
\begin{equation}
    \text{VRAM}_{\text{used}} + K \cdot 45\text{~MB} < B_v, \quad P_t < B_p, \quad T_t < B_T
\end{equation}

\noindent \textbf{Controller Components:}
\begin{itemize}
    \item \textbf{Throughput Estimator ($\widehat{\text{TPS}}$):} Estimates tokens/second from sequence entropy $H_t = -\sum p_i \log p_i$ and layer retention ratio.
    \item \textbf{VRAM Barrier:} If available VRAM $< 500\text{~MB}$, high $K$ is penalized. If free VRAM $< 100\text{~MB}$, the action is rejected.
    \item \textbf{Thermal Barrier:} If GPU junction temperature $T_t \ge 82^\circ\text{C}$, the controller forces aggressive layer shedding ($S \to \texttt{cka\_50}, K=1$) to prevent hardware thermal throttling.
\end{itemize}

\section{Limitations \& Hardware Roofline Boundary}
\label{sec:limitations}

On entry-level mobile GPUs with 96-bit memory buses (192~GB/s), single-token forward passes take only $\approx 20\text{~ms}$. Because draft passes execute 75\% of model layers and verify passes evaluate $K+1$ tokens, the break-even acceptance rate is high:
\begin{equation}
    \alpha_{\text{break-even}} = \frac{T_{\text{draft}} + T_{\text{verify}} - T_{\text{vanilla}}}{K \cdot T_{\text{vanilla}}}
\end{equation}
On higher-bandwidth server platforms (e.g., RTX 4090 with 1008~GB/s or A100 with 2039~GB/s), parallel compute headroom allows self-speculative decoding to achieve substantial speedups ($>1.4\times$).

\section{Conclusion}
\label{sec:conclusion}

We presented \textbf{ZASSD}, a zero-additional-model-weight self-speculative decoding framework tailored for edge GPUs. By coupling empirical layer-skipping with pre-allocated static KV buffers, hybrid prompt-lookup drafting, and closed-loop hardware control, ZASSD eliminates auxiliary draft weights (saving 1.5--3.0~GB VRAM) while achieving up to 89.1\% acceptance, robust thermal protection, and verified numerical stability within the 4-bit quantization envelope.
